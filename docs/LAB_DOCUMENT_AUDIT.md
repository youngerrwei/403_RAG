## 观察

1. 根目录 8 份 Markdown 中，2 份包含 HTML 表格，共 9 个表。旧清洗直接删除标签，会把单元格粘在一起。
2. 表内存在空格、空单元格、合并跨度及源 OCR 错位。单纯恢复表格结构不能修复错误识别内容。
3. 制度/拍摄要求等有短条款，幻灯片有大量短章节和图片占位；用固定长度过滤会同时误删有效说明、误留带长标题前缀的低信息内容。
4. 设备目录包含中英文手册、软件安装包和很深的 SDK 目录；会议资料混合个人收获和研究内容，不能把“提到设备”当成“设备操作规范”。
5. 有界遍历只作抽样，不代表全盘覆盖，也不能用某次扫描遇到的 Markdown 数推断全盘文档数量。

## 部署与验收

1. 先核对远端未提交修改与实际 Web 入口；备份源 Markdown 和 Qdrant。
2. 同步经过审核的源码（包括新增 `src/lab_rag/document_structure.py`）和配置；检查 `ENABLE_HYDE=false`、`MIN_STRUCTURED_CHUNK_LENGTH=12`。
3. 核对异常表、短条款及设备型号。已损坏源文本应先重转或人工核对，禁止代码补写规则。
4. 确认挂载和知识库目录完整后，在维护窗口执行 `bash scripts/auto_ingest.sh --full`。本轮切分/文本变化需要重建；不要对局部文档目录重建生产全集。
5. 执行 `bash scripts/start_rag.sh restart`，确认健康接口，再检查实际检索片段和引用。
6. 用独立验收集覆盖制度、不同组别设备操作、中英文参数、版本冲突、目录清单、证据不足、多轮追问。人工标注期望来源和原文依据，比较修改前后命中、证据忠实度与延迟；测试问题不能成为线上问句匹配分支。

离线结构回归：

```bash
python -m unittest discover -s tests -p test_evidence_pipeline.py -v
```

运行时链路仍有可改进项：全文匹配通道不是 BM25；复杂合并/跨页表、目录/正文混合查询的覆盖范围，以及独立人工评测集仍需进一步验证。本轮不宣称这些问题已全部解决。
