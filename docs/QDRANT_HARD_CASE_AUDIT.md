# Qdrant 难样本回放（2026-10-05）

## 范围

经用户指定 SSH 主机访问 `lab_knowledge_base`，集合有 25,821 个子块；5 个全文字段均为 multilingual 文本索引、最小词长 2。Web 健康接口为 `ok`，MCP 内部检索 Token 未配置，因此没有调用该接口，也未绕过认证。

抽样先读取按 ID 排序的 12 个子块，再沿其中型号和章节做有界条件检索，人工核对英文正文，选取 4 个首屏漏召回的证据锚点。这是目的性难样本挖掘，不是均匀随机抽样或独立测试集；不能推广为全库准确率。

本地新检索模块以源码传入远端独立 Python 进程内存，连接真实数据库只读执行；未写共享盘、生产代码、索引或用户会话，未重启服务、加载第二套 GPU 模型。另验证实际 qdrant-client 可处理嵌套过滤及 `with_vectors=False`。

## 已复现的原因

- 旧全文通道将型号、正文意图和完整查询全部 OR，取前 64 个 point；scroll 是 ID 顺序，不是相关性排名。
- LETO-3 + Reset Adjustments 的 OR 匹配有 3,068 个候选，跨字段同时匹配两个词项只有 3 个；PROPSIM + 带宽命令对应 4,378 与 4 个。
- 用 `set` 生成关键词再裁前 30 个字段条件，可能随机丢掉查询词；旧包装还丢失 `header_path`、`source` 等 metadata。
- 抽样中有 `<think>` 生成摘要及非常短的实际正文。全文匹配不能让摘要中的猜测提高原文相关性；本次只禁止其贡献本地匹配排序分，不声称旧向量污染已经消除。

## 固定查询词回放结果

中文问题是便于人工理解的标签；实际 `query` 和 `keywords` 固定为从原文得到的英文型号/章节词，不经过 LLM 改写。基线为旧 OR+首屏逻辑，词序固定以便复现；每例共 15 个字段条件，不涉及旧裁剪上限。两侧 `top_k=64`，新方案候选总预算 256。

| 期望原文证据 | 旧前 64 | 旧扩大至 256 的排名 | 新前 64 排名 |
| --- | --- | --- | ---: |
| LETO-3：右键点击调整框标题可单独重置 | 未命中 | 未命中 | 2 |
| PROPSIM：`GROup:BANDWidth:SET` 参数语法 | 未命中 | 未命中 | 3 |
| APD210：低温运输后带包装回温，防止凝露 | 未命中 | 118 | 1 |
| EDU36311A：查询过压状态、用 CLEAR 清零 | 未命中 | 未命中 | 16 |

这 4 个证据锚点的全文通道 Recall@64 为 **0/4 → 4/4**。即使把旧首屏扩到 256，仍漏掉其中 3 个。单次测得旧调用 9–12 ms，新调用 33–42 ms；这是小样本单次耗时，不是性能压测或 P95。

新逻辑通用于所有词项：组合条件加独立通道，各自分配预算；以原文、章节、来源覆盖率排序，稳定去重和 ID 同分兜底，保留所有 metadata。无任何设备或问题专用规则。纯本地匹配不等同于 Qdrant 分词，零匹配候选保留给后续语义重排；摘要不贡献本地分数，但仍可能触发数据库候选召回。

## 复现

```bash
conda run -n rag python scripts/evaluate_lexical_retrieval.py --top-k 64
python -m unittest discover -s tests -p test_lexical_retrieval.py -v
```

样本在 `tests/fixtures/qdrant_hard_cases.json`，记录中文问题标签、固定检索词、point ID 和必要原文证据字符串。脚本使用 `.env` 指定数据库；只执行 point 读取与 scroll。目标正文已变化时显式失败，需重新核对，禁止静默改期望答案迎合结果。

## 未覆盖项与下一步

1. 未验证中文改写能否得到上述英文词项；跨语言改写是独立待测项。
2. 没有测 Dense、RRF、Reranker、父块展开及最终生成的联合准确率。全文找回证据不保证最终被选入上下文，也不保证答案完整。
3. EDU36311A 目标仅排第 16；同目录的通用应用指南可能先出现，不能将目录中的厂商通用建议视为该型号专属参数。仍需语义重排、适用范围核对和独立验收。
4. 旧生成摘要、超短残句、转换表格仍需此前的清洗和重新入库方案；本次没有修改这些生产数据。
5. 部署前核对远端脏工作区；只部署本次检索变更不要求重建，但此前分块变更依然要求备份后全量重建。
